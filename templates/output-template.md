# 输出契约（每次运行默认遵循）

对外报告是写给求职者看的修改指南，不是审计底稿。必须且只按下面四段输出。
内部仍可按验证协议打分、对照岗位 rubric、挖掘价值，但这些过程表不要原样倾倒给用户。

```markdown
# 简历诊断

## 1. 初步结论

**评估范围：** [目标岗位] · [职级方向] · [目标市场] · [有/无职位描述]
（若是自定义岗位：补一句「按 xx 标准近似评估」）

[用 2–4 句写总评：这份简历能不能撑起该定位；最能打动人的地方；最影响阅读或录用的不足。写人话，不要空泛套话。]

**亮点**
- [一条具体亮点，点到简历里的产物或结果]
- …

**不足**
- [一条具体不足，让读者立刻知道差在哪]
- …

## 2. 各维度评分

分数只看简历上写出来的证据，不是对本人真实能力的鉴定。

| 维度 | 分数 /5 | 简历上的依据 |
|------|---------|--------------|
| 扫视可读性 |  | [一句话，指向具体版面或结构现象] |
| 成果化程度 |  | [一句话，引用看得见的结果] |
| 量化与可核实 |  | [一句话，说明数字是否完整、口径能否讲清] |
| 系统读取 |  | [一句话：复制或抽取后，姓名、公司、日期是否还在正确位置] |
| 岗位匹配度 |  | [一句话，点出已具备和仍弱的能力信号] |
| 诚实与一致性 |  | [一句话] |
| 市场适配 |  | [一句话] |

依据栏用白话写证据；如需溯源，把标准 ID 放在句末括号里，例如（G-SCAN-10s）。
不要再附完整的岗位能力对照总表。

「系统读取」说的是：很多公司会用招聘系统自动抽取你的姓名、公司、日期和技能（这类系统英文叫 ATS，即 Applicant Tracking System）。对外必须写清这句人话，不要只丢一个 ATS 缩写。国内投递且没有明显读取问题时，不要把这项写成主要不足或高优先级修改；外企，或用户明确走官网网申时，再作为重点说明。若低分来自 Boss 等平台导出的水印或碎片，注明这是导出噪音，不是经历内容差。

## 3. 优先修改建议

按对录用的影响从高到低排列。编号必须是 P1、P2、P3……每个数字只用一次。
通常写 4–6 条；同类问题合并成一条。不要把所有问题都标成 P1。

### P1：[一句话标题，直接点出问题]

- **问题：** 用大白话说清楚哪里不好、读者会怎么理解偏。
- **原文：** 「……」
- **为什么要改：** 用一句人话说明招聘方会因此怎样判断（标准 ID 放句末括号，如 G-XYZ、AMZ-DATA）。
- **建议改成：**
  > 写出可直接采用的完整句子。未知信息写成 [待补：……]，禁止虚构。
- **需要你补充：** 具体问什么；没做过的不要补写。若无需补充，删除本行。

### P2：[……]

## 4. 总结

用 3–6 句收束，覆盖下面这些意思即可，不要再拆成新的大节：

- 最值得保留的经历和数字（点到为止）
- 如果版面需要压缩：一句话说清压到几页、主要靠去重还是删旧项目
- 下一步先改哪 1–3 件事
- 动笔前最需要你确认的问题（例如投递方向、关键数字口径）

未提供职位描述时，写明「本次不做具体职位的关键词覆盖判断」。
若提供了职位描述，用一张很小的表列出尚未覆盖的高优先级关键词，放在本段开头即可。
```

完整改写稿仅在用户明确要求时追加，放在总结之后，标题为「完整改写稿」。

协议：

1. 四段齐全；不要把「审计口径」「能力对照」「价值提炼表」「改写对照」「建议页安排」写成与这四段平行的大节。
2. 每条优先修改建议必须同时有：唯一编号、问题、原文、为什么要改、建议改成。缺任何一项视为未完成，须重写该条。
3. 「为什么要改」必须能追溯到标准 ID（写在括号里即可），但正文必须是人话，不能只用 ID 代替解释。
4. 「建议改成」必须是完整、可粘贴的句子，不能只给抽象方向。
5. 禁止虚构；缺证据用 `[待补]` 或向用户追问。
